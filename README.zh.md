# dsh-web-search

DeepSeek Harness 的 **web profile** 插件。通过 DuckDuckGo 和 Bing 提供免费联网搜索，不需要 DeepSeek 搜索密钥。

- [English](./README.md)

它从 [`dsh-fixes`](../dsh-fixes) 中拆分出来，需要单独安装。

## 能做什么

| 部分 | 说明 |
| --- | --- |
| 搜索提供方 | 在 Harness `web` 上注册 `duckduckgo` 提供方；网页行选择它 |
| 引擎 | DuckDuckGo 的 HTML 结果和 Bing 的网页结果。没有官方搜索 API。 |
| 引擎顺序 | 默认自动测速排序，也可以在「通用」设置里指定固定顺序。见下文。 |
| 开关 | 「通用」设置里的「启用联网搜索」。关闭后，智能体不能再调用搜索。每次提供工具时都会读取，不需要重启。 |

`web_fetch` 不受影响，仍使用 Harness 自带的 `http` 提供方。

## 引擎顺序

在「搜索引擎顺序」里三选一：

- **自动（测速排序）**，默认。第一次搜索时，用固定的探测词同时查询两个引擎，每个引擎只要一条结果，单个引擎最多等 5 秒。能返回结果的排在前面，快的在前；没返回结果的按默认顺序排在后面。排序结果在内存里保留 10 分钟。如果两个引擎都没有返回结果，这次排序不会被保留，下次搜索会重新探测。每个 10 分钟窗口里的第一次搜索，可能会多花大约 5 秒。
- **DuckDuckGo → Bing** 或 **Bing → DuckDuckGo**。跳过探测，直接按所选顺序尝试。

无论哪种模式，搜索都按顺序逐个尝试引擎。某个引擎出错或没有结果，就交给下一个。所有引擎都没有结果，返回空结果；所有引擎都失败，则报告每个引擎的失败原因。固定顺序时，另一个引擎仍然作为兜底。

## 安装

在本目录：

```sh
npm install
npm run build
```

然后通过 Harness 的插件管理器把插件装进 profile（`install_bundle`，目标为本目录）。

开发：

```sh
npm test
npm run typecheck
```

仓库：https://github.com/Meteor-system/dsh-web-search

## 设置

插件自有命名空间 `dsh-web-search`：

```yaml
dsh-web-search:
  enabled: true
  engineOrder: []        # [] = 自动测速；或者如 ["bing", "duckduckgo"]
```

| 字段 | 含义 |
| --- | --- |
| `enabled` | 缺省或任何非 `false` 的值都表示开启。 |
| `engineOrder` | `[]` 表示自动探测。非空列表按顺序尝试；列表里没有的引擎按默认顺序补到末尾，无法识别的名字会被忽略。 |

## 升级注意

开关以前放在 `dsh-fixes` 里（`webSearchEnabled`），现在移到了这里。旧键下保存的值会被忽略，所以迁移后开关会恢复为开启。

## 限制

- 搜索结果来自 HTML 页面，DuckDuckGo 或 Bing 改版时，解析可能失败但不会报硬错误。
- 两个提供方都可能对自动化流量发起验证；这时智能体拿到的是失败的搜索，而不是结果。
- 搜索请求不使用系统代理。在直连 DuckDuckGo 会超时的机器上（例如系统代理环境），所有搜索都来自 Bing，并且每个窗口的第一次搜索要承担探测的时间。
- 工具输出不显示是哪个引擎返回的结果，智能体无法判断结果来自哪个引擎。
- 排序结果只保存在进程内存中，重启后会重新探测。
- 只支持这两个引擎；第三方搜索 API 不在范围内。
